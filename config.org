* Emacs Config
** Startup performance
Garbage-collection tuning lives in ~early-init.el~. It has to run before this
file is tangled and loaded, otherwise it misses most of startup's allocation.
** File header
The first tangled block supplies ~config.el~'s header line. It must stay first:
Emacs only honours a ~lexical-binding~ cookie on line 1 of a file, and without
it the whole configuration is evaluated with dynamic binding.

#+BEGIN_SRC emacs-lisp
  ;;; config.el --- Tangled from config.org -*- lexical-binding: t; -*-
#+END_SRC
** Package initialization
#+BEGIN_SRC emacs-lisp
  (require 'package)

  ;; `package-enable-at-startup' and `package-quickstart' are set in
  ;; early-init.el -- both are read before this file loads, so setting them here
  ;; had no effect on the current session.

  (add-to-list 'package-archives '("gnu" . "https://elpa.gnu.org/packages/"))
  (add-to-list 'package-archives '("melpa" . "https://melpa.org/packages/"))

  ;; Interactively, startup has already run `package-activate-all' by the time
  ;; this file loads, so activating again would just repeat the work. Under
  ;; `emacs --batch -l init.el' it has not: startup's guard also requires
  ;; `user-init-file', which batch leaves nil. Test the same flag
  ;; `package-activate-all' sets, so each case does the work exactly once.
  (unless (bound-and-true-p package--activated)
    (package-initialize))

  ;; Refresh package list asynchronously to avoid blocking startup
  (unless package-archive-contents
    (package-refresh-contents t))

  ;; use-package is built-in to Emacs 29+
  (require 'use-package)
  (setq use-package-always-ensure t)

  (setq load-prefer-newer t)
#+END_SRC

** General config
*** User variables
Define custom user variables that get set once per machine. Bootstrap
by customizing the ~agg~ group and use Apply and Save to save the
values to the ~custom.el~ for future sessions.

#+BEGIN_SRC bash
  customize-group <RET>
  agg
#+END_SRC

Identity variables deliberately live *outside* this group. ~user-full-name~
already arrives correct from the OS (macOS supplies it from the account's
RealName), and ~user-mail-address~ is a standard ~defcustom~ in
~startup.el~ -- set it with =M-x customize-variable RET user-mail-address=
if anything ever needs it. Redeclaring either here only risked persisting an
empty default over a value that was already right. The same applies to
~system-name~ and ~user-login-name~.

*** Editor
#+BEGIN_SRC emacs-lisp
  (use-package emacs
    :ensure nil
    :custom
    ;; TAB cycle if there are only few candidates
    ;; (completion-cycle-threshold 3)

    ;; Enable indentation+completion using the TAB key.
    ;; `completion-at-point' is often bound to M-TAB.
    (tab-always-indent 'complete)

    ;; Emacs 30 and newer: Disable Ispell completion function.
    ;; Try `cape-dict' as an alternative.
    (text-mode-ispell-word-completion nil)

    ;; Hide commands in M-x which do not apply to the current mode.  Corfu
    ;; commands are hidden, since they are not used via M-x. This setting is
    ;; useful beyond Corfu.
    (read-extended-command-predicate #'command-completion-default-include-p))

  ;; ---------------------------------------------------------------------------
  ;; The `use-package emacs' form ends above. Everything below is plain
  ;; top-level configuration -- it was previously indented as though it were
  ;; still inside that form, which made the scope read wrongly.
  ;; ---------------------------------------------------------------------------

  ;; Note: *inhibit-startup-message* and *inhibit-splash-screen* are aliases for this variable
  ;; Turn off startup splash
  (setq inhibit-startup-screen t)

  ;; Turn off menu
  (menu-bar-mode -1)

  ;; Turn off tool-bar
  (when (fboundp 'tool-bar-mode)
    (tool-bar-mode -1))

  ;; Turn off scroll-bar
  (when (fboundp 'scroll-bar-mode)
    (scroll-bar-mode -1))

  ;; Turn off initial scratch buffer text message
  (setq initial-scratch-message nil)

  ;; Disable line wrap. `default-truncate-lines' has not existed for many
  ;; versions -- setting it was a silent no-op, so lines were still wrapping.
  ;; Toggle per-buffer with F12 (`toggle-truncate-lines', bound below).
  (setq-default truncate-lines t)

  ;; Display line and column numbers
  (setq line-number-mode t)
  (setq column-number-mode t)

  ;; Prompt - use short yes/no answers
  (setq use-short-answers t)

  ;; Change backups to go to a backup directory
  (setq backup-directory-alist '(("." . "~/.emacs.d/backups")))

  ;; Auto revert all files changed elsewhere.
  ;; Use polling instead of file notifications: on macOS the kqueue
  ;; backend watches a file's descriptor, which is invalidated when the
  ;; file is rewritten on save. auto-revert tears the watch down and an
  ;; in-flight event can hit it while its callback is momentarily nil,
  ;; producing "file-notify--call-handler: Symbol's function definition
  ;; is void: nil". Polling sidesteps the race entirely.
  (setq auto-revert-use-notify nil)
  (global-auto-revert-mode t)

  ;; Set pager to cat for shell
  (setenv "PAGER" "/bin/cat")

  ;; Compilation buffer

  ;; Scroll with output automatically
  (setq compilation-scroll-output t)
  ;;(setq compilation-scroll-output 'first-error)

  ;; Show on top of current buffer instead of new buffer.
  ;; same-window-buffer-names has been obsolete since 24.3.
  (add-to-list 'display-buffer-alist
               '("\\*compilation\\*" display-buffer-same-window))

  ;; Smooth scrolling (Emacs 29+, feels native on macOS trackpads)
  (pixel-scroll-precision-mode 1)

    "Insert the current date in ISO format.
  With one prefix argument use the local locale's date format; with two,
  write out the day and month name."

  ;; Trackpad suppression while Emacs has focus (Linux/X11 only). Stops stray
  ;; palm contact moving point while typing.
  (defun agg/set-trackpad (enable)
    "Enable the trackpad when ENABLE is non-nil, otherwise disable it.
  Uses call-process rather than `shell-command' because this runs on every
  focus change: DESTINATION 0 discards output and returns without waiting, so
  there is no synchronous shell and no \"succeeded with no output\" echo. A
  no-op where xinput is unavailable, which keeps it quiet on macOS and on
  Linux hosts without it."
    (when (executable-find "xinput")
      (call-process "xinput" nil 0 nil
                    (if enable "--enable" "--disable")
                    agg-trackpad-device)))

  (defun agg/turn-off-mouse (&optional _frame)
    "Disable the laptop trackpad."
    (interactive)
    (agg/set-trackpad nil))

  (defun agg/turn-on-mouse (&optional _frame)
    "Re-enable the laptop trackpad."
    (interactive)
    (agg/set-trackpad t))

  (defun agg/update-trackpad-for-focus ()
    "Disable the trackpad while Emacs is focused, re-enable it when it is not."
    (if (frame-focus-state)
        (agg/turn-off-mouse)
      (agg/turn-on-mouse)))

  (defun agg/register-mouse-hooks ()
    "Suppress the trackpad while Emacs holds focus.
  `focus-in-hook' and `focus-out-hook' were used here originally; both have
  been obsolete since 27.1 and the byte-compiler flags them. Their replacement
  `after-focus-change-function' fires for focus gained *and* lost, so a single
  handler has to branch on `frame-focus-state' -- adding both turn-on and
  turn-off to it, as an earlier attempt in this file did, cannot work.

  The trackpad is always re-enabled when a frame is deleted or Emacs exits,
  otherwise it would be left disabled outside Emacs."
    (add-function :after after-focus-change-function
                  #'agg/update-trackpad-for-focus)
    (add-hook 'delete-frame-functions #'agg/turn-on-mouse)
    (add-hook 'kill-emacs-hook #'agg/turn-on-mouse))

  (when (eq system-type 'gnu/linux)
    (agg/register-mouse-hooks))

  (defun agg/insert-ruby-debug-print (start end)
    "Insert a Ruby debug print for the expression between START and END.
  With `foo' selected, adds a line above the current one reading

    puts \"foo=#{foo}\"

  Replaces an opaque keyboard-macro vector that did the same thing through
  `kmacro-exec-ring-item', obsolete as of 29.1."
    (interactive "r")
    (let ((expr (buffer-substring-no-properties start end)))
      (beginning-of-line)
      (insert (format "puts \"%s=#{%s}\"\n" expr expr))
      (forward-line -1)
      (indent-according-to-mode)
      (forward-line 1)))

#+begin_src emacs-lisp
  ;; Remap traditional modes to tree-sitter modes (built-in to Emacs 29+).
  ;; Entries are (LANGUAGE CLASSIC-MODE . TS-MODE). Each remap is installed
  ;; only when its grammar is actually present, so a missing grammar degrades
  ;; to the classic mode rather than erroring when a file is opened.
  ;; eval-and-compile so the byte-compiler also sees treesit's definitions;
  ;; the `nil t' keeps this harmless on a build without tree-sitter support.
  (eval-and-compile (require 'treesit nil t))

  (when (and (featurep 'treesit) (treesit-available-p))
    (dolist (entry '((bash       sh-mode      . bash-ts-mode)
                     (css        css-mode     . css-ts-mode)
                     (json       js-json-mode . json-ts-mode)
                     (python     python-mode  . python-ts-mode)))
      (when (treesit-ready-p (car entry) t)
        (add-to-list 'major-mode-remap-alist (cdr entry))))

    ;; Explicit extension entries. add-to-list prepends, so these win over any
    ;; entry a third-party package's autoloads may have registered.

    ;; A remap only fires when auto-mode-alist names the exact mode used as the
    ;; key, so these two need explicit extension entries instead:
    ;;
    ;;   .go  -- unclaimed by default, and go-mode is not installed
    ;;   .js  -- auto-mode-alist names `javascript-mode', an alias for js-mode;
    ;;           the remap lookup does not resolve aliases, so a (js-mode . _)
    ;;           key never matched and js-ts-mode-hook never ran. That hook
    ;;           carries eglot-ensure, add-node-modules-path, apheleia and
    ;;           smartparens, so JS buffers were silently getting none of them.
    ;;   .yaml/.yml -- Emacs ships no auto-mode entry for YAML at all
    ;;   .json -- Emacs' own entry names js-json-mode (handled by the remap
    ;;           above), but an installed json-mode package registers .json for
    ;;           itself and would otherwise win
    ;;
    ;; The YAML and JSON entries previously worked only by accident: undeclared
    ;; yaml-mode and json-mode packages were sitting in elpa/, so a clean
    ;; rebuild (the documented "rm -rf elpa" test) would have dropped YAML to
    ;; fundamental-mode and taken json-ts-mode-hook and apheleia with it.
    (when (treesit-ready-p 'go t)
      (add-to-list 'auto-mode-alist '("\\.go\\'" . go-ts-mode)))
    (when (treesit-ready-p 'javascript t)
      (add-to-list 'auto-mode-alist '("\\.[cm]?js\\'" . js-ts-mode)))
    (when (treesit-ready-p 'yaml t)
      (add-to-list 'auto-mode-alist '("\\.ya?ml\\'" . yaml-ts-mode)))
    (when (treesit-ready-p 'json t)
      (add-to-list 'auto-mode-alist '("\\.json\\'" . json-ts-mode))))

  ;; html-mode is deliberately not remapped: auto-mode-alist sends .html to
  ;; mhtml-mode, which is a distinct mode (not an alias), so an (html-mode . _)
  ;; key never fired. mhtml-mode is kept on purpose -- it sub-modes embedded
  ;; <script>/<style> blocks, which html-ts-mode does not. html-mode-hook still
  ;; runs, since mhtml-mode derives from html-mode.

  ;; ruby-mode is deliberately not remapped: enh-ruby-mode claims .rb via
  ;; auto-mode-alist (see the Ruby section), so a ruby-ts-mode remap could
  ;; never fire. The surrounding tooling -- robe, rubocop, ruby-tools,
  ;; inf-ruby, projectile-rails -- is all built around enh-ruby-mode.

  ;; Grammar sources for M-x treesit-install-language-grammar
  (setq treesit-language-source-alist
        '((bash "https://github.com/tree-sitter/tree-sitter-bash")
          (css "https://github.com/tree-sitter/tree-sitter-css")
          (go "https://github.com/tree-sitter/tree-sitter-go")
          (html "https://github.com/tree-sitter/tree-sitter-html")
          (javascript "https://github.com/tree-sitter/tree-sitter-javascript" "master" "src")
          (json "https://github.com/tree-sitter/tree-sitter-json")
          (python "https://github.com/tree-sitter/tree-sitter-python")
          (ruby "https://github.com/tree-sitter/tree-sitter-ruby" "master" "src")
          (tsx "https://github.com/tree-sitter/tree-sitter-typescript" "master" "tsx/src")
          (typescript "https://github.com/tree-sitter/tree-sitter-typescript" "master" "typescript/src")
          (yaml "https://github.com/ikatyang/tree-sitter-yaml")))

#+BEGIN_SRC emacs-lisp
  ;; How to get a token
  ;; Run this command to describe the process of saving token and cookie
  ;; M-x slack-refresh-token

  ;; The short version is to grab:
  ;; token xoxc-XXXX
  ;; d    xoxd-YYYY
  ;; d-s  123
  ;; lc   456
  ;; combine to make:
  ;; xoxd-YYYY; d-s=123; lc=456

  ;; See this to get it working with enterprise tokens:
  ;; https://github.com/emacs-slack/emacs-slack/commit/472c48673f21148d85c069e8f404584349e780ca

  ;; auth-sources is deliberately left at its default,
  ;; ("~/.authinfo" "~/.authinfo.gpg" "~/.netrc"). Setting it to just
  ;; ("~/.authinfo") only narrowed that list, dropping the encrypted option
  ;; while gaining nothing. Prefer ~/.authinfo.gpg -- these are live Slack
  ;; session tokens, and the plain file stores them in cleartext.

  ;; == ~/.authinfo.gpg contents ==
  ;; machine clojurians.slack.com user token password "xoxc-XXX"

* Notes
** Clean test
Occasionally, I like to test my init files from a clean environment so
I know I haven't messed something up along the way. To do this, I do
the following:

1. Close Emacs
1. Checkout the git revision you think should work (start with main)
1. Clean the existing ELPA compiled directory

   ~/src/dotemacs $ rm -rf elpa

1. Start Emacs

   Repeat all steps until you get a clean launch. If you don't get a
   clean start, go back to a previous revision in the git log until
   you do.

   It would be nice to have something like a build server that would
   perform a "clean build" on all new configuration changes.
