# AGENTS.md

Guidance for coding agents working in this repository. See [`README.md`](README.md)
for the human-facing version.

## Overview

A personal Emacs configuration using **literate programming** with Org-mode. The
configuration is written as an Org document with embedded elisp code blocks.

## Architecture

- **`config.org`** — The configuration. **Edit this and only this.** Organised
  hierarchically by topic; find the right section before adding anything.
- **`init.el`** — Two-line entry point: `(org-babel-load-file "~/.emacs.d/config.org")`.
- **`config.el`** — Generated by tangling `config.org`. Gitignored. **Never edit**;
  changes are silently overwritten on next load.
- **`custom.el`** — Machine-specific settings written by Emacs' customize system.
  Gitignored, so it is **invisible to `grep` over tracked files** — but it is
  loaded at startup and holds real values. Check it before concluding a variable
  is unset.
- **`tests/`** — ERT suite and the byte-compile warning gate.
- **`Makefile`** — Every check below.

## Verifying changes

**Always run `make check` after editing `config.org`.** It is exactly what CI
runs, and it takes a few seconds.

| Command | What it does |
| --- | --- |
| `make check` | `lint` + `test`. Run this before every commit. |
| `make test` | Loads the config, runs the ERT suite (`tests/config-test.el`). |
| `make lint` | Tangles and byte-compiles `config.org`; fails on any **new** warning. |
| `make tangle` | Writes `config.el` without loading it. |
| `make grammars` | Installs the tree-sitter grammars the config declares. |
| `make baseline` | Re-records the byte-compile warning baseline. |
| `make clean-tangle` | Deletes the generated `config.el`. |

To run one test:

```sh
emacs --batch -l init.el -l tests/config-test.el \
  --eval '(ert-run-tests-batch-and-exit "config-progmode-cleanup-stays-buffer-local")' </dev/null
```

### The warning baseline

`make lint` compares byte-compile output against `tests/warning-baseline.txt`
rather than demanding zero warnings, because the config carries a backlog of
benign "assignment to free variable" warnings from setting options before their
libraries load. **New warnings fail the build.**

If a change legitimately removes warnings, the run reports them as fixed and you
should tighten the baseline with `make baseline`, committing the result alongside
the change. Never run `make baseline` to silence a warning you introduced.

### Adding tests

`tests/config-test.el` separates **invariants** (properties that should hold for
any future edit — no `*-mode-hook` may reference an undefined function, no
`major-mode-remap-alist` key may name a nonexistent mode) from **regressions**
(specific past bugs). Prefer an invariant when the bug represents a class of
mistake; it catches more than the one instance.

Tests should `skip-unless` rather than fail when the environment genuinely cannot
support them (a tree-sitter grammar that will not build, an absent `custom.el`),
and must log what they skipped. A silent pass is worse than either.

## Two things the test suite cannot catch

- **New code blocks must be `#+begin_src emacs-lisp`.** `org-babel-load-file`
  tangles only `"emacs-lisp\|elisp"`, so a block in any other language is
  silently dropped from `config.el` — the code simply never runs, with no error.
- **Redirect `</dev/null` when running `emacs --batch` by hand.** vterm prompts
  to build its native module and will otherwise hang forever. The Makefile
  targets already do this.

Everything else worth knowing is enforced by `make check`; read the failing test
name rather than guessing.

## Package management

`use-package` with MELPA and GNU ELPA:

```elisp
(use-package package-name
  :ensure t
  :config ...)
```

Use `:ensure nil` for built-ins. Any package the config relies on must be
declared here — a package present in `elpa/` but undeclared is a latent break,
since `rm -rf elpa` is the documented clean-test procedure.

## Custom variables

Genuinely machine-specific values belong in the `agg` group, set via
`M-x customize-group RET agg` so they persist to `custom.el`:

```elisp
(defcustom agg-something "default"
  "Description."
  :type 'string
  :group 'agg)
```

Do not redeclare built-in variables to pull them into the group; several already
arrive correct from the OS, and a `""` default risks overwriting a good value.

## CI

`.github/workflows/check.yml` runs `make lint` and `make test` on Emacs 30.1 and
`snapshot` for pushes and pull requests. `snapshot` is non-blocking but worth
reading — it is where deprecations surface first.

Requires **Emacs 30 or newer**.
