# dotemacs

[![check](https://github.com/agoodno/dotemacs/actions/workflows/check.yml/badge.svg)](https://github.com/agoodno/dotemacs/actions/workflows/check.yml)

A personal Emacs configuration written as a literate Org document.
**[`config.org`](config.org) is the configuration** — everything else in this
repo exists to load it, test it, or explain it.

## Layout

| Path | Role |
| --- | --- |
| [`config.org`](config.org) | The configuration. ~69 `use-package` declarations, organised by topic. Edit this. |
| `init.el` | Two lines: hands `config.org` to `org-babel-load-file`. |
| `config.el` | Generated by tangling `config.org`. Gitignored. Never edit. |
| `custom.el` | Machine-specific values written by `M-x customize`. Gitignored, so it differs per machine. |
| `custom-themes/` | Hand-written themes (`agg-light`, `agg-dark`). |
| `lisp/` | Load path for local elisp. |
| `vendor/` | Load path for checked-out third-party elisp. Gitignored, and every use of it is guarded, so a fresh clone works without it. |
| `tests/` | ERT suite and the byte-compile warning gate. |
| `Makefile` | Entry point for everything below. |

## Requirements

Emacs **30 or newer**. The config relies on `use-package`, `eglot`, and the
`*-ts-mode` family being built in, and on `text-mode-ispell-word-completion`
(Emacs 30). CI covers 30.1 and `snapshot`.

Tree-sitter grammars are needed for the major-mode remaps. They are guarded on
`treesit-ready-p`, so a missing grammar quietly falls back to the classic mode
rather than erroring — run `make grammars` to install them all.

## Setting up a new machine

```sh
git clone git@github.com:agoodno/dotemacs.git ~/.emacs.d
cd ~/.emacs.d
emacs --batch -l init.el   # installs packages; takes a while the first time
make grammars              # build the tree-sitter grammars
make check                 # confirm the result is sane
```

Then set the machine-specific values with `M-x customize-group RET agg`
(org-roam directories) and `M-x customize-themes` for the theme. Those land in
`custom.el`, which is deliberately not committed.

## Notes: two org-roam trees, personal and work

Each tree keeps its database beside its own notes, so the two never mix:

| Directory | `defcustom` | Holds |
| --- | --- | --- |
| `~/notes/` | `agg-org-roam-personal-directory` | Personal notes |
| `~/Google Drive/My Drive/sonosnotes/` | `agg-org-roam-work-directory` | Work notes |

Both paths are machine-specific and set through `M-x customize-group RET agg`.

| Command | Effect |
| --- | --- |
| `agg/roam-toggle-notes` | Flip between the two. From work it goes personal; from anywhere else — including an unrecognized `org-roam-directory` — it goes to work, so a stray value resolves to a known state. |
| `agg/roam-switch-to-work-notes` | Go to the work notes, wherever you started. |
| `agg/roam-switch-to-personal-notes` | Go to the personal notes, wherever you started. |

Each repoints `org-roam-directory` *and* `org-roam-db-location`, then rebuilds
that tree's database. Nothing is bound to a key; reach them from `M-x`.

**Which tree you start in is a `custom.el` decision, not a `config.org` one.**
`org-roam-directory` is an ordinary defcustom, and forcing a value from
`config.org` once pointed org-roam at a directory that did not exist on the
machine and let autosync build an empty database there;
`config-does-not-override-org-roam-directory` in `tests/config-test.el` guards
against a repeat. To change which notes load at startup, customize
`org-roam-directory` itself — the switch commands above do not persist.

`config.org` sets only the other half at startup: `org-roam-db-location`, which
has no per-machine setting and would otherwise keep its default under
`user-emacs-directory`, leaving a fresh session pointed at the notes from
`custom.el` while reading a stale `~/.emacs.d/org-roam.db`. It derives the
location from whatever directory `custom.el` names, without a database rebuild
— `org-roam-db-autosync-mode` keeps it current from there.

**Do not also set `org-roam-db-location` in `custom.el`.** `custom.el` loads
early, while the derivation runs from org-roam's `:config` block whenever
org-roam first loads, so a customized value is set and then overwritten — it
looks authoritative and does nothing. Worse, it would be a second source of
truth: change the notes directory and a hand-set database location silently
keeps pointing at the old tree. Set the directory only; the database follows.

## Diagnostics: flycheck and flymake, deliberately both

Two diagnostic systems run, each owning the buffers it is better at.

| | Owns | Why |
| --- | --- | --- |
| **flymake** | LSP-managed buffers — TypeScript, TSX, JavaScript | Built in, and the only system `eglot` reports through |
| **flycheck** | everything else | Ships ready-made checkers for the external linters used here — shellcheck, yamllint, jq, xmllint, `ruby -w` |

`agg/flycheck-defer-to-eglot` runs from `eglot-managed-mode-hook` and switches
flycheck off when eglot takes a buffer, back on when it releases it. Without
that, TypeScript buffers got annotated twice — which reads as one checker being
noisy rather than as two systems overlapping.

`M-g f` is bound to `agg/consult-diagnostics`, which dispatches to
`consult-flymake` or `consult-flycheck` depending on which is live. Binding it
straight at either one is wrong for most buffers.

**Why not flymake alone?** It was measured, not assumed. With the external
linters installed the two are at parity on shell, YAML, JSON and XML. flycheck
is ahead on Ruby, because `flymake-collection` targets `ruby-mode` while this
config uses `enh-ruby-mode`. flymake's apparent lead on Emacs Lisp is four
`checkdoc` style notes, and `emacs-lisp-checkdoc` is disabled here precisely to
avoid those. So flymake-only would have added a dependency and lost `html-tidy`
without improving a single diagnostic. It remains a reasonable future move —
flymake and eglot are both core, and the test suite makes switching cheap — but
it buys nothing today.

**External linters.** Several checkers are inert without their CLI tool. Present
and working: `shellcheck`, `yamllint`, `jq`, `xmllint`, `ruby`. `eslint`
resolves per project via `add-node-modules-path` rather than globally, so it
works inside a repo that depends on it and nowhere else.

**Emacs Lisp needs trust.** Emacs 30 gates byte-compilation of untrusted code
(CVE-2024-53920), which is what elisp diagnostics rely on, so
`trusted-content` is set to `("~/.emacs.d/")`. Buffers with no file — `*scratch*`
in particular — cannot match a directory prefix and so get no elisp checker
regardless; that is why `flycheck-global-modes` excludes
`lisp-interaction-mode`.

## Development

| Command | What it does |
| --- | --- |
| `make check` | `lint` + `test`. This is exactly what CI runs. |
| `make test` | Loads the config and runs the ERT suite (14 tests). |
| `make lint` | Tangles and byte-compiles `config.org`, failing on any *new* warning. |
| `make tangle` | Writes `config.el` from `config.org` without loading it. |
| `make grammars` | Installs every tree-sitter grammar the config declares. |
| `make baseline` | Re-records the byte-compile warning baseline (see below). |
| `make clean-tangle` | Removes the generated `config.el`. |
| `make help` | Lists the above. |

After editing `config.org`, reload with
`M-x org-babel-load-file RET ~/.emacs.d/config.org`, or restart Emacs.

### How the tests work

`tests/config-test.el` holds two kinds of check:

- **Invariants** that should hold for any future edit — no `*-mode-hook` may
  reference an undefined function, no `major-mode-remap-alist` key may name a
  nonexistent mode, save-time cleanup may never reach the *global*
  `before-save-hook`, hook functions may not mutate global values, and every
  bound key must resolve to a live command.
- **Regressions** pinning specific past bugs — extension-to-mode dispatch
  (verified through real `find-file`, since remap lookup does not resolve mode
  aliases), which command wins a contested key once load order settles, theme
  discoverability, and that `config.org` does not override values `custom.el`
  owns.

Some tests skip rather than fail when the environment cannot support them — a
grammar that will not build, or a `custom.el` that is absent as it is in CI.
Skips are logged, never silent.

### The warning baseline

`config.org` carries 49 long-standing byte-compile warnings, mostly the benign
"assignment to free variable" kind that comes from setting an option before its
library loads. Demanding zero would mean either a large cleanup first or
ignoring warnings forever, so `make lint` compares against
`tests/warning-baseline.txt` instead: **new warnings fail, the existing backlog
stays visible.** Warnings that disappear are reported so the baseline can be
tightened with `make baseline`.

Positions are stripped before comparison so the baseline survives line-number
churn, and collation is pinned to `LC_ALL=C` so a baseline recorded on macOS
compares correctly on Linux.

The exact set varies slightly by environment — which libraries happen to be
loaded when the compiler runs affects the free-variable warnings. Only *new*
warnings fail, so a smaller set elsewhere is harmless.

## CI

`.github/workflows/check.yml` runs `make lint` and `make test` on Emacs 30.1 and
`snapshot`. `snapshot` is non-blocking, since it breaks for reasons unrelated to
this config — though it is also where forward-compatibility problems surface
first, so its failures are worth reading.

The workflow checks out to `$HOME/.emacs.d` with `HOME` pointed at the
workspace, because `init.el` resolves `config.org` by absolute path. That also
sandboxes the run, which matters: loading this config starts a server and writes
`recentf`, `savehist`, `places`, and `org-roam.db`.
